# 建模说明

CatSense V0 当前有一个本地 baseline 模型。它的作用是验证数据和训练流程，不是最终猫咪行为分类器。

## 输入数据

处理脚本读取：

```text
data/raw/{cat_id}/manual_*.csv
```

然后输出：

```text
data/processed/unified_samples.csv
data/processed/features.csv
```

训练脚本默认排除空标签。空标签表示未知或不确定行为，不参与训练。

## 训练流程

网页操作：停止记录后，在网页底部“数据处理”面板点“一键全部”。这个按钮会先构建数据，再训练 baseline，并继续做 Session 评估。

流程：

1. 读取 raw CSV
2. 转成统一样本格式
3. 过滤空标签
4. 按文件、猫编号、标签和时间连续性切成片段
5. 对每个有标签片段头尾做边缘裁剪
6. 用 2 秒窗口、1 秒步长生成样本
7. 提取统计特征
8. 标准化特征
9. 训练 nearest-centroid 分类器
10. 输出模型和报告

输出：

```text
data/processed/features.csv
data/processed/windows.csv
models/baseline_centroid.json
models/baseline_report.txt
```

## 窗口设置

当前默认：

| 参数 | 值 |
| --- | --- |
| 窗口长度 | 2 秒 |
| 步长 | 1 秒 |
| 训练采样率 | 25 Hz |
| 每窗口样本数 | 约 50 |
| 默认边缘裁剪 | 头尾各 0.8 秒 |

窗口太短会看不出行为模式，太长会混入多个行为。2 秒是 V0 的保守起点。

## 边缘裁剪

手动标记经常会有反应时间误差：开始按钮可能按晚，结束按钮也可能按晚。为了减少片段头尾的混合动作污染，训练脚本默认不会直接使用整个标签片段，而是先裁掉每个片段的开头和结尾。

默认：

```text
trim_edge_s = 0.8
```

含义：

- 原始 CSV 不会被修改。
- 每个连续标签片段头部丢 0.8 秒。
- 每个连续标签片段尾部丢 0.8 秒。
- 裁剪后放不下一个 2 秒窗口的短片段不会参与训练。
- 报告会记录用了多少片段、丢了多少行。

网页流程默认启用裁剪。一般不建议禁用；如果后续确实要暴露这个参数，应该做成网页设置，而不是日常手动改命令。

如果你经常来不及点结束，边缘裁剪尤其有用，因为尾部最容易混入下一个动作。

## 特征

每个窗口会计算：

- `ax/ay/az` 的均值、标准差、最小值、最大值、范围、RMS
- `ax/ay/az` 的 25 分位和 75 分位
- 加速度模长 `mag`
- 相邻样本差分 `d_ax/d_ay/d_az/d_mag`
- 窗口时长
- 样本数

这些特征描述的是一段时间内的运动强度、稳定性、姿态变化和冲击程度。

## nearest-centroid 原理

训练时，每个标签会得到一个中心点：

```text
label_center = 该标签所有窗口特征向量的平均值
```

预测时，把新窗口的特征向量和每个标签中心点比较，距离最近的标签就是原始预测。

这个模型简单、可解释、依赖少，适合 V0。但它不是强模型。

## 当前 baseline 结果

最近一次随机窗口训练：

```text
windows=1236
labels=eat,groom,parkour,play,rest,walk
trim_edge_s=0.800
train_accuracy=0.730
test_accuracy=0.718
```

解释：

- 数据链路已经跑通
- 能生成模型文件
- 能在网页实时预测预览
- 准确率还不能作为公开性能宣传
- `roll` 和 `litter` 已从当前标签集合停用，历史停用标签不再参与训练

## 按 Session 评估

随机窗口划分会把同一次录制里的相邻窗口同时放进训练集和测试集，结果会偏乐观。更严格的检查是每次留出一个 CSV 文件作为测试 session，其余文件训练。网页“Session 评估”按钮会执行这个检查，“一键全部”也会包含它。

最近一次 session holdout 结果：

```text
sessions=16/16
windows=1236
accuracy=0.576
```

各类表现：

| 标签 | precision | recall | f1 | support |
| --- | ---: | ---: | ---: | ---: |
| `eat` | 0.665 | 0.957 | 0.784 | 253 |
| `groom` | 0.408 | 0.207 | 0.275 | 203 |
| `parkour` | 0.902 | 0.807 | 0.852 | 114 |
| `play` | 0.711 | 0.598 | 0.649 | 251 |
| `rest` | 0.546 | 0.494 | 0.519 | 251 |
| `walk` | 0.271 | 0.378 | 0.316 | 164 |

结论：

- `eat`、`parkour` 相对稳。
- `groom` 和 `walk` 跨 session 泛化差，需要补更干净、更多样的数据。
- 这个结果更适合写进开源说明，随机窗口准确率只能作为流程检查。

## 实时预测预览

网页采集器默认加载：

```text
models/baseline_centroid.json
```

实时流程：

1. 缓存最近约 2 秒样本
2. 按模型窗口设置重采样
3. 提取同样的特征
4. 与每个类别中心点计算距离
5. 转成相对稳定度分数
6. 对连续窗口做平滑
7. 只有新标签连续出现并超过门槛时才切换显示
8. 通过 SSE 推送到网页

禁用实时预测：

```bash
python web_logger.py --no-prediction
```

## 分数不是概率

网页里的百分比是相对稳定度，不是概率。

如果多个行为中心点距离接近，就会看到：

- 分数都差不多
- 显示“观察中”
- 显示“低置信”
- 原始预测可能和稳定显示不同

这是正常现象，说明当前模型还不能清楚区分这些动作。

## 当前弱点

已知问题：

- `groom`、`walk`、`play` 容易混
- 当前测试划分是随机窗口划分，偏乐观
- 同一录制片段里的相邻窗口很相似
- 佩戴位置和松紧程度还没有充分覆盖

## 后续模型要求

要做成更可用的 V0 模型，需要：

- 每类至少 5-10 分钟真实佩戴数据
- 多天、多环境、多佩戴状态
- 按 session 或日期切分训练/测试
- 单独评估每类 recall
- 给出混淆矩阵
- 记录模型版本、标签 schema、窗口参数
- 尝试更强模型，例如树模型或轻量神经网络

## 什么时候该相信模型

当前模型只能作为观察参考。

可以相信的内容：

- 数据是否大致可分
- 哪些标签容易混
- 实时链路是否通
- 平滑逻辑是否可用

不能承诺：

- 对新猫稳定准确
- 对不同项圈佩戴都准确
- 可检测健康异常
- 可替代人工标记

# 系统原理

这篇文档解释 CatSense V0 为什么这样设计，以及每一层在做什么。

## 总体链路

```text
猫咪动作
  -> 项圈随身体运动
  -> IMU 测到三轴加速度
  -> nRF52840 固件打包成 CSV 行
  -> BLE Notify 发给电脑
  -> Python 网关保存 CSV
  -> 网页手动标记行为
  -> 网页数据处理切窗口、提特征、训练 baseline
  -> 网页实时预测预览
```

核心思想：先把真实世界的项圈运动变成时间序列数据，再把人工标记的行为片段变成可训练样本。

## 为什么用 IMU

IMU 是惯性测量单元。XIAO nRF52840 Sense 板载 IMU，可以测到加速度和角速度。V0 当前只使用三轴加速度：

- `ax_mg`
- `ay_mg`
- `az_mg`

单位是 `mg`，其中 `1000 mg` 约等于 `1 g` 重力加速度。

猫咪行为会让项圈产生不同运动模式：

- 休息：三轴比较稳定，主要看到重力方向
- 走动：周期性小幅波动
- 跑酷：短时大幅冲击和快速变化
- 舔毛：头颈部有重复小动作
- 进食：低头、咀嚼和轻微移动

这些模式不一定每次都很清楚，所以需要真实佩戴数据和足够多的场景。

## 为什么不直接识别姿态

项圈会转动，设备可能在脖子上方、下方或侧面。三轴方向和猫身体方向不固定。

所以 V0 的模型不直接假设：

- X 轴一定朝前
- Y 轴一定朝左
- Z 轴一定朝上

它更多依赖窗口内统计特征，例如强度、波动、范围和差分，而不是固定姿态规则。

## 固件做什么

固件运行在 XIAO nRF52840 Sense 上。

主要任务：

1. 初始化 IMU
2. 初始化 BLE
3. 广播设备名 `CatSense-V0`
4. 接收主机命令
5. 按设定频率采样
6. 读取电池电压
7. 通过 BLE Notify 发出文本数据

采样数据格式：

```csv
CS0,seq,device_ms,ax_mg,ay_mg,az_mg,battery_mv
```

例如：

```csv
CS0,1234,567890,12,-45,1010,3970
```

`seq` 是样本序号，`device_ms` 是设备运行毫秒数。这两个字段用于检查丢包、断连和采样间隔。

## 为什么用 BLE UART

V0 使用 Nordic UART Service 风格的 BLE 协议。

优点：

- 实现简单
- 手机、电脑、树莓派都容易连接
- 调试方便
- 文本协议容易抓日志

缺点：

- 吞吐量有限
- 连接稳定性受距离、姿态、外壳和电脑蓝牙影响
- 不适合大量离线缓存

V0 的目标是先跑通原型，所以选择简单可靠的文本协议。

## Python 网关做什么

Python 网关在电脑或树莓派上运行。

它负责：

- 扫描 BLE 设备
- 连接 `CatSense-V0`
- 发送 `RATE 25` 或 `RATE 50`
- 发送 `START`
- 接收 Notify 数据
- 解析 `CS0,...` 行
- 写入 CSV
- 给网页推送实时曲线和状态
- 记录手动标签
- 加载 baseline 模型做实时预测预览

命令行采集器适合快速测试。网页采集器适合真实数据采集，因为可以边看曲线边手动标记。

## 手动标签为什么重要

模型不知道猫在做什么。它只能学习“某段传感器数据对应什么标签”。

人工标记就是监督学习里的真值。

错标的影响很大：

- 把舔毛错标成走动，会让模型认为舔毛像走动
- 把混合动作整段标成一个类，会让模型学到模糊边界
- 不确定时留空，比强行标错更好

V0 的网页设计成“按下开始、再按结束”，就是为了降低标记成本。

## CSV 数据是什么

网页采集器保存的 CSV 包含：

```csv
host_time_iso,device_ms,seq,ax_mg,ay_mg,az_mg,battery_mv,label,cat_id,device_id,marker,marker_time_iso,marker_note
```

关键字段：

- `device_ms`：设备时间，用于切窗口和检查间隔
- `seq`：样本序号，用于检查丢样
- `ax_mg/ay_mg/az_mg`：三轴加速度
- `battery_mv`：电池电压
- `label`：当前手动标签
- `marker`：标签开始或结束事件

训练时只使用有 `label` 的行。空标签会被丢弃。

## 为什么要切窗口

单个样本只有一个瞬间的三轴值，信息太少。行为识别通常需要看一段时间。

当前 baseline 使用：

- 窗口长度：2 秒
- 步长：1 秒
- 采样率：25 Hz
- 每个窗口约 50 个样本

窗口表示一小段连续动作。模型判断的是这 2 秒内更像哪个行为。

## 特征提取原理

训练脚本不会直接把 50 个点全部塞进模型，而是先提取统计特征。

每个窗口会计算：

- 每个轴的均值
- 标准差
- 最小值和最大值
- 范围
- RMS
- 25 分位和 75 分位
- 合加速度模长
- 一阶差分统计
- 窗口时长和样本数

合加速度模长：

```text
mag = sqrt(ax^2 + ay^2 + az^2)
```

差分表示相邻样本变化量：

```text
d_ax[i] = abs(ax[i] - ax[i-1])
```

差分越大，说明动作变化越剧烈。跑酷通常差分大，休息通常差分小。

## 当前 baseline 模型原理

当前模型是 nearest-centroid，中文可以理解为“最近中心点分类器”。

训练过程：

1. 对每个有标签窗口提取特征
2. 对特征做标准化
3. 按标签分组
4. 计算每个标签的平均特征向量
5. 这个平均向量就是该标签的中心点

预测过程：

1. 对实时窗口提取同样的特征
2. 用训练时的均值和标准差做标准化
3. 计算它到每个标签中心点的距离
4. 距离最近的标签就是原始预测

优点：

- 没有复杂依赖
- 容易解释
- 适合验证数据链路

缺点：

- 表达能力弱
- 类别相近时容易混
- 分数不是概率
- 对佩戴方式变化敏感

## 为什么预测百分比会接近

网页上的分数来自“距离有多接近”，不是严格概率。

如果一个窗口到多个类别中心点距离都差不多，就会出现：

- 多个类别分数接近
- 预测来回跳
- 稳定度不高

这不是网页坏了，而是当前数据和模型还不能明确区分这些动作。

## 为什么要做平滑

实时窗口每 0.5 秒更新一次。如果每次都直接显示原始预测，页面会频繁跳。

V0 现在做了两层处理：

1. 对连续窗口的类别分数做指数平滑
2. 新标签必须连续出现，并且超过当前显示标签一定幅度，才切换

这叫切换迟滞。它不会让模型更聪明，但可以让显示更稳定，更适合观察。

## 为什么数据质量比数量更重要

更多数据通常有帮助，但前提是：

- 标签准确
- 动作真实
- 场景丰富
- 类别均衡
- 佩戴状态有变化

错误标注会直接污染模型。少量干净数据比大量混乱数据更有价值。

## 真实可用模型还需要什么

后续需要：

- 多天采集
- 多猫采集
- 多种佩戴松紧和位置
- 按录制 session 或日期划分训练/测试
- 更强模型，例如树模型或轻量神经网络
- 更严格的混淆矩阵和召回率评估

当前 V0 的价值是证明端到端链路成立，并为后续开源协作打基础。

# 数据采集规范

CatSense V0 的标签是手动标签。网页会持续记录数据，点击行为按钮会把后续样本标成当前行为，再点同一个按钮会清空标签。

## 标签集合

| CSV 标签 | 网页中文 | 含义 |
| --- | --- | --- |
| `rest` | 休息 | 躺着、坐着、安静休息 |
| `parkour` | 跑酷 | 快跑、跳跃、爬高、突然爆发 |
| `walk` | 走动 | 正常走路或慢速移动 |
| `play` | 玩耍 | 玩逗猫棒、玩玩具，但强度不到跑酷 |
| `groom` | 舔毛 | 舔身体、梳理毛发 |
| `eat` | 进食 | 吃干粮、湿粮或零食 |

## 标记原则

- 只在确定行为时打标签。
- 过渡状态、混合动作、不确定动作留空。
- 宁可少标，也不要错标。
- 尽量采真实佩戴行为，不要只用手晃板子替代。
- 同一只猫固定使用同一个 `cat_id`。

## 单次采集建议

推荐短而干净的片段：

- 每段 10-60 秒
- 行为清楚
- 开始和结束尽量准确
- 中间混入其他行为时及时结束标签

不推荐：

- 一段标记十几分钟但中间动作混杂
- 不看猫，只凭猜测标记
- 设备没戴在项圈上却标成真实行为

## 保存方式

网页采集器支持三种保存方式：

| 模式 | 文件 | 说明 |
| --- | --- | --- |
| `daily` | `manual_YYYYMMDD.csv` | 默认模式，同一天多次开始/停止都追加到一个 CSV |
| `session` | `manual_YYYYMMDD_HHMMSS.csv` | 每次开始记录生成一个新 CSV |
| `preview` | 不写文件 | 只看曲线、手动标签状态和实时预测 |

推荐日常采集使用 `daily`，这样不会产生太多 CSV。需要严格分开每次录制时再用 `session`。

注意：`preview` 模式不会保存任何训练数据。它适合调试设备、看实时预测，不适合采集数据。

## 标记来不及时怎么办

训练脚本默认会在每个连续标签片段头尾各裁掉 0.8 秒，这样可以减少手动反应慢造成的边缘污染。

这意味着：

- 原始 CSV 会完整保存，不会被改。
- 训练时优先使用片段中间更干净的部分。
- 如果结束按钮按晚了，尾部混入的下一动作会更少进入训练。
- 如果片段太短，裁剪后放不下 2 秒窗口，就不会用于训练。

所以采集时不需要为了按按钮过度紧张，但仍然要尽量准确。推荐每段至少 10 秒以上，给裁剪和窗口留出空间。

## 项圈佩戴记录

采集时尽量记录这些信息：

- 松紧程度：偏松、正常、偏紧
- 设备位置：脖子下方、侧面、上方
- 是否容易转动
- 是否有外壳
- 电池固定方式
- 是否在充电

这些因素会改变加速度模式。后续整理自采开源样例数据时，最好把这些信息作为 session metadata 保存。

## 数据量目标

不是越多越好，而是高质量、均衡、覆盖充分的数据越多越好。

V0 建议：

| 阶段 | 每类目标 |
| --- | ---: |
| 最小可用 | 30 秒 |
| 第一版 baseline | 120 秒 |
| 更可靠原型 | 5-10 分钟 |
| 开源样例数据 | 多猫、多天、多佩戴状态 |

优先补：

1. 容易混淆类：`walk`、`groom`、`play`
2. 不同佩戴位置
3. 不同日期和环境

## 断连时会发生什么

如果还没点结束标记就断开：

- 已写入的样本保留当前标签
- CSV 会 flush 并关闭
- 不会自动补一个结束 marker
- 下一次采集从空标签开始

这对训练是可以接受的，因为网页数据处理流程只使用已经写入的样本，并按连续片段切窗口。

## 质量检查

采集结束后，停止记录，在网页底部“数据处理”面板点“检查数据”。

重点关注：

- `parse_errors > 0`
- 某些标签秒数太少
- 某些文件采样率明显异常
- `time_gaps` 很多
- `seq_gaps` 很多
- 某段标签明显和真实行为不一致

## 什么时候该重新采

遇到这些情况建议重采：

- 设备没有固定好，频繁甩动
- 猫在做多个动作，但整段只标了一个标签
- 采样频率严重不稳定
- 断连太频繁，单段很短
- 明显把标签点错了
